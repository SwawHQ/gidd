## Execution conventions

Use this repository’s gidd.link .git / .gh for Git and GitHub operations. Explicit user instructions and existing task authorization take precedence over this preset.
In this spec, commit means creating commits and pushing them. Report these two outcomes separately if pushing fails; honor a request to commit without pushing.
Ask policies apply to the named workflow decisions, not every read or implementation step. Do not ask again for an action already explicitly authorized for the same scope.

## Implementation and validation

Implement the agreed scope while preserving the user's changes. Check each acceptance criterion, run relevant tests, and record passing, failing and unverified items.
Keep any Issue or PR consistent with the final scope and validation. Prepare a concrete, reviewable result before requesting approval for a later stage.

## Delivery record

For Git delivery, verify the remote commit identifiers on the target branch. Record validation and remaining work on the associated Issue or PR and in the final report.
A local commit or a pushed development branch alone is not completed delivery to the target branch. Keep partial work open and explain what remains.
