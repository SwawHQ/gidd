# 测试约定与后续修订

测试只验证 gidd 的行为。正常 Git 操作使用现成 Git 和临时仓库。GitHub 请求使用可控响应，避免依赖开发者账号和网络。

## 本次修订

- 进程、管道和取消测试使用 Node 执行 JS 辅助脚本，移除 `pipe-parent.cs` 和 `fixture-worker.cs`。
- Windows Job Object 的进程清理程序继续保留。它负责在测试退出或超时后停止后代进程。
- 安装和命令入口测试仍需要少量可控的原生工具探针。同一份源码在每个测试进程中只编译一次，再复制到各自临时目录。损坏一个副本不会影响后续测试。
- Git 和 Node 的固定路径在测试进程内复用。故意变化的模拟工具不缓存版本或状态。
- 夹具清理只恢复一次环境。停止子进程失败时，先恢复环境，再报告错误并保留目录供后续清理。关闭的夹具不能再请求 PowerShell 适配器或启动受管异步进程。
- Git 和 gh 的安装恢复测试分成两个用例，分别保留原有 120 秒上限。没有提高超时。
- ZIP 夹具和安装下载映射由 JS 生成。ZIP 只用于小型测试数据，使用运行时内置 CRC32，不增加依赖。
- JS 根据调用选择被测脚本，PowerShell 只加载收到的脚本列表。解析语法时不加载产品模块；进程、完整性、配置和解压检查只加载各自依赖。
- 适配器共用本地下载替身。安装、绑定、恢复和路径保护仍执行真实产品函数。
- 准备、安装和版本解析共用响应查找；删除未使用的版本解析联网分支。缺少测试响应时直接失败。
- 恢复成功已校验负载和绑定，不再每个阶段另起进程重复校验。等价路径检查使用四组代表输入，分别检查健康和损坏状态。
- 任务测试按登记与授权方案、Issue 创建、工作区准备、交付和本地合并拆成五个文件，共用一份夹具。`dev.cmd .test-node issue-task` 和 `.test-bun issue-task` 仍运行整组；每个文件独立使用原有 900 秒上限。
- 任务夹具将测试取消信号传给命令，关闭时主动取消，并等待进行中的操作结束。自动清理会等待异步关闭，再删除目录。
- MinGit 和运行时的四个安装中断阶段直接检查恢复结果，不再另起 PowerShell 重复校验。两个用例共减少八次启动；初次完整性检查、损坏检查和相邻工具保护检查继续保留。
- 工作树根目录、Git 目录和公共目录在一次 Git 查询中读取。工作树入口复用管理目录检查已读到的信息；加锁后的读取和修改前后的复核继续保留。
- 仅调用仓库本身时，目录范围检查复用刚读取的路径。调用另一个工作树时仍检查其管理记录。纯 Git 连接不再紧接着重复读取远端配置；授权后、远端操作前仍重新校验。

## 本轮补充检查

- 数据巡检复用现有路径查询函数，每个工作树由两次 Git 查询减为一次。缺失或格式错误的路径信息仍报告仓库不匹配。
- 任务命令复用加锁后刚读取的公共目录，每次命令减少一次 Git 查询。从 Issue 创建流程接收的上下文可能跨越 GitHub 请求，仍重新读取。
- 对比使用本机临时小仓库、真实 Git 和 GitHub 测试响应。准备工作区、状态、合并、推送和清理五个操作共减少五次 Git 调用。单次计时会受环境波动影响，不据此承诺固定提速。

继续优化前，先测量剩余成本。本轮 Node 计时如下：

| 项目 | 测量结果 | 处理 |
| --- | --- | --- |
| GitHub 连接内重新定位管理目录 | 两次 Git 查询，约 70～85 毫秒 | 保留现有定位和归属检查，暂不增加上下文传递 |
| 单个任务夹具准备 | 约 1.2 秒，其中 11 次仓库准备操作约 1.04 秒 | 保留每个用例独立的真实仓库，暂不增加模板缓存 |
| 含 Node 程序的完整文件快照 | 程序约 88.5 MiB，五次快照平均约 82 毫秒 | 保留内容哈希，不以大小或修改时间替代 |

以上计时不包含真实网络请求。测试准备和快照未改变；不跨命令缓存路径、分支或远端配置。

## 保留的 PowerShell

原适配器中的 ZIP 生成、下载文件映射、编译转发、辅助进程启动和管道子进程清理分支已删除。ZIP 生成、下载映射和模块选择只保留 JS 实现。

测试相关的 PowerShell 目前各有一个用途：

- `tests/support/windows.ps1`：调用真实产品函数，并注入本地下载或安装故障。ZIP 解压、锁、完整性和中断恢复继续测试真实实现。
- `dev/compile-test-process.ps1`：编译保留的 Windows 进程清理程序和原生工具探针。测试适配器不再提供另一份编译入口。
- `dev/windows.ps1`：开发命令的入口，负责工具选择、准备和运行测试。它是被测对象。

产品目录中的 PowerShell 仍是正式实现。例如 `setup-tools/download.ps1` 负责解压和路径保护，不能随测试 ZIP 生成器一起删除。

## 入口测试精简

- 每个已移除的命令名保留一次拒绝检查。路由在读取参数前拒绝这些命令，不再按不同参数或配置键重复启动入口。
- 损坏 TOML、无效语言和配置缺失三种状态继续检查。完整参数形状在一组状态中验证，其余状态保留未知命令、参数错误和标准错误输出的代表检查。
- 终端语言独立性由配置单元测试验证。入口测试为三种配置状态各配一个终端语言，不再重复完整交叉组合。
- 每种帮助语言读取一次，帮助别名与已读取文本比较。原始参数、空参数、引号、中文、标准输入输出、退出码、超时和后代进程的独立边界测试继续保留。
- 完整文件内容快照、配置修改时间和文件标识检查继续保留。无效语言写入的快照范围扩展到整个临时用户目录，覆盖共享配置文件。

## 原生探针清理

- 删除没有调用者的 auth-gh.cs。
- 删除 wrapper-gh.cs 中没有调用者的 Git 子进程、凭据助手、环境回显及认证错误模式分支。
- 账号并行隔离使用现有执行注入接口，由 JS 检查参数、令牌变量、账号结果和调用方环境。非交互环境默认值直接检查返回对象。
- 普通 Git 测试仅准备 Git 仓库和提交身份，不再绑定 gh 或创建无关的 GIDD 配置及数据目录。独占文件锁用例单独编译所需探针。

保留的三个工具探针各有一个原生边界用途：

| 源码 | 保留原因 |
| --- | --- |
| tool.cs | 提供可控的版本、失败和超时响应，覆盖真实工具准备及命令入口 |
| wrapper-gh.cs | 覆盖原生参数与输入输出、登录输出和 Windows 独占文件锁 |
| transport-git.cs | 已安装入口调用真实 Git，仅在传输命令中把 GitHub 地址映射到本地裸仓库 |

Windows Job Object 清理程序另行保留，继续负责超时、取消和父进程退出后的后代进程清理。没有新增探针、依赖或产品配置。

## 可以继续精简

- 继续按单例耗时检查跨模块重复的 Git 查询。完整交付场景仍是主要耗时来源。路径合并和入口信息复用已完成；分支、配置及远端的阶段复核继续保留。
- 检查重复的大文件快照。只验证无写入时，可以缩小快照范围；涉及文件保护的断言继续保留。
- 入口中未知命令和配置状态的重复组合已合并。后续仅在确认覆盖同一执行边界时继续合并；参数转发、管道和进程退出仍各有独立检查。

开发时先运行相关测试组。完整检查保留完成标记和进程清理。所有夹具放在系统临时目录，结束后清理。
