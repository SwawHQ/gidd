## 执行约定

通过本仓库的 gidd.link .git / .gh 操作 Git 和 GitHub。用户的明确指令及本任务已有授权优先于预设。
  本规范中的 commit 包含创建提交和推送远端；推送失败时分别报告两步结果，用户要求只提交不推送时按其要求执行。
询问策略针对指定流程节点，不要求每次读取或实现步骤都询问；同一范围内已有明确授权的操作不重复询问。

## 实现与验证

按约定范围完成修改，保留用户的改动。逐项核对验收条件，执行相关测试，记录通过、失败及未验证事项。
让已有 Issue 或 PR 与最终范围及验证结果一致。需要批准后续阶段时，先完成可供审阅的具体结果。

## 交付记录

需要 Git 交付时，核对目标分支上的远端提交标识，在关联 Issue 或 PR 及最终报告中记录验证与剩余工作。
仅本地提交或仅推送开发分支不代表目标分支已收到交付；部分完成时保留未完成状态并说明剩余事项。
