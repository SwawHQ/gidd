# 环节参考经验

本目录的 TOML 文件保存各环节可选的 GIDD 工具说明。通用 Git 操作由 Agent 自行处理。同一环节在不同交付模式下的说明集中在一个文件中，由程序按模式选择。步骤顺序由程序固定，授权方案由 `flows/` 中的配置提供，具体规则见 [工作流程配置](../../flows/README.md)。

文件名中的编号用于浏览和查找环节，不决定执行顺序。每个文件按以下格式保存说明：

```toml
[zh-CN."*"]
title = "commit"
body = '''
提交参考经验。
'''

[en."*"]
title = ""
body = ""
```

TOML 表名由语言和交付模式匹配表达式组成，例如 `[zh-CN."*"]` 表示适用于所有模式的中文说明。交付模式匹配表达式匹配去掉目录编号后的完整交付模式名：`00.direct-commit` 使用 `direct-commit` 匹配。表达式中的 `*` 可以匹配任意字符，其余字符按原样匹配。

中文和英文的交付模式匹配表达式须覆盖相同的一组交付模式。同一文件中，每个模式在每种语言下最多匹配一段正文，不能叠加多段说明。生成工作流程时，只加载该模式适用的环节；文件或正文可以省略；提供正文时须有唯一匹配。参考经验补充操作说明，不增加环节，也不改变执行顺序。

英文表中的 `title` 和 `body` 暂留空，待中文定稿后统一翻译。中文说明编写完成后，用 `gidd flow <交付模式编号>/<授权方案编号> --lang zh` 检查它在完整工作流程提示中的实际内容。
